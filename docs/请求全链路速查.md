# 请求全链路速查(从一行测试代码到 HTTP 响应)

> 面试高频题:"从你按下回车到拿到响应,中间发生了什么?"
> 这篇用**本项目的真实代码**回答,每一层都有具体行号和实测值。

---

## 一句话版本

```
测试用例 → 业务层(api/) → 传输层(utils/http_client.py) → requests → socket
   → uvicorn → Starlette(路由匹配) → FastAPI(解析依赖) → 路由函数 → crud → SQLite
   → 序列化 JSON → socket → requests 组装 Response → 回到用例断言
```

---

## 0. 以 `todo_api.get_todo(42)` 为例

```python
def get_todo(self, todo_id: int | str) -> requests.Response:
    return self.client.get(f"/todos/{todo_id}", headers=self._headers())
```

实测这一行进入传输层时的真实参数:

```
[HttpClient.request] method=GET  path='/todos/42'
                     kwargs={'headers': {'Authorization': 'Bearer ...'}}
[HttpClient.request] url = http://127.0.0.1:8000/todos/42
[HttpClient.request] 交给 requests: method='GET' url=... timeout=5 headers={'Authorization': ...}
```

**注意:两处求值都发生在"发请求之前"** —— `f"/todos/{42}"` 拼字符串、`self._headers()` 造头。**头是客户端造的,服务端只负责读。**

---

## 1. 客户端六个阶段

| 阶段 | 位置 | 做什么 | 失败时的典型现象 |
|---|---|---|---|
| ① 用例 | `testcases/business/` | 调业务层方法,拿到 Response 再断言 | `AttributeError` / 断言失败 |
| ② 业务层 | `api/todo_api.py` | 拼路径、组 header,不判断结果 | `InvalidURL`(路径少写 `/`) |
| ③ 传输层 | `utils/http_client.py:request()` | 拼完整 URL、补超时、合并默认头、调 requests、打日志 | `InvalidURL` / 头丢了导致 401 |
| ④ requests | 第三方 | 连接池、组报文、走 socket | `ConnectionError`(服务没起) |
| ⑤ 网络 | — | TCP/TLS | `Timeout` / `SSLError` |
| ⑥ 服务端 | 见下 | 见下 | 4xx / 5xx |

### ③ 的六个动作(按顺序)

```python
url = f"{self.base_url}{path}"                                  # a) 拼 URL
kwargs.setdefault("timeout", self.timeout)                       # b) 补超时
headers = {**self.default_headers, **kwargs.pop("headers")}      # c) 合并头(显式优先)
if headers: kwargs["headers"] = headers
response = self.session.request(method, url, **kwargs)           # d) ★ 真正发请求(阻塞)
logger.info(f"[HTTP] {method} {response.url} -> {response.status_code}")   # e) 打日志
return response                                                  # f) 返回信封
```

> **日志在 e) 打** —— 所以 `run.log` 里的时间戳是"**响应已经回来之后**",不是发出时。

### ④ 实际发出的报文(和 `curl -v` 几乎一致)

```http
GET /todos/42 HTTP/1.1
Host: 127.0.0.1:8000
Authorization: Bearer xxx
User-Agent: python-requests/2.34.2      ← curl 这里是 curl/8.5.0,其余相同
Accept-Encoding: gzip, deflate
Connection: keep-alive
```

**所以 curl 能复现 requests 的问题** —— 它们发的是同一种报文。

## 2. 服务端五个阶段

```
uvicorn 收到字节
 └─ Starlette 按【注册顺序】匹配 (GET, /todos/{todo_id})
      └─ FastAPI 把路径参数 "42" → int 42        ← 转不了就 400 INVALID_PARAM
           └─ 解析 Depends:
                get_db()                       → Session
                get_current_user(Bearer 头)     → User   ← 没 token 在这就 401,函数体不执行
                └─ 调用 get_todo(todo_id=42, db=Session, current_user=User)
                     └─ crud.get_todo → SQLAlchemy → sqlite3
                          SELECT * FROM todos WHERE id=42 AND deleted=0
                     └─ 归属校验失败 → raise forbidden() → 403
           └─ 返回值按 response_model=TodoOut 序列化 → JSON
```

## 3. 回到客户端

```
socket 收到字节 → urllib3 → requests 组装 Response
   r.status_code / r.json() / r.headers / r.elapsed 立即可用
   ↑ 因为 session.request() 是【同步阻塞】的,收完才返回
```

## 4. 故障定位表(最实用的一页)

| 现象 | 卡在哪 | 怎么验证 |
|---|---|---|
| `ModuleNotFoundError` | ① 之前 → `sys.path` | 打印 `sys.path`;检查 `pytest.ini` 的 `pythonpath` |
| `InvalidURL` / `MissingSchema` | ②③ | `print(url)`;路径必须以 `/` 开头 |
| `ConnectionError` / `Connection refused` | ④ | `curl $BASE/docs` 看服务活没活 |
| `Timeout` | ⑤ | 加 `--max-time`;看服务端日志有没有收到请求 |
| `401 UNAUTHORIZED` | ⑥ 依赖阶段 | `curl -v` 看 `Authorization` 头发出去没 |
| `400 INVALID_PARAM` 但参数没错 | **⑥ 路由匹配** | 检查是否被 `{param}` 通配路由抢先匹配 |
| `403 FORBIDDEN` | ⑥ 函数体 | 确认当前账号与资源归属 |
| `404` | ⑥ crud | 资源是否被软删除(`deleted=1`) |
| `500` | ⑥ 函数体抛异常 | 看 uvicorn 终端的 traceback |
| 用例过了但库里没有 | ⑥ 写库 | **双端校验**:直接 `db.query()` 核对 |

## 5. `curl` / `requests` / 浏览器 的关系

| | 浏览器 | curl | requests |
|---|---|---|---|
| 方法 | 基本只有 GET/POST | 任意(`-X`) | 任意 |
| 改 header | 不能 | `-H` | `headers={}` |
| 看响应头 | 开发者工具 | `-i` | `r.headers` |
| 看请求头 | 开发者工具 | `-v` | `r.request.headers` |
| 脚本化 | 不能 | shell | Python |
| 用途 | 手动看页面 | **排查/复现** | **写用例** |

三者发出去的报文**是同一种东西**。所以排查顺序通常是:**curl 复现** → **requests 编写例** → **进 CI**。

## 6. 面试 30 秒版答案

> "一行 `get_todo(42)` 会依次经过业务层拼路径和鉴权头、传输层拼 URL 并合并默认头、requests 组报文走 socket;
> 服务端 uvicorn 收包后 Starlette 先按注册顺序匹配路由,FastAPI 解析路径参数和 Depends(数据库会话、当前用户),
> 再调路由函数进 crud 查库;返回值按 response_model 序列化回 JSON。
> 所以链路上每一段都可能出问题:**401 在依赖阶段就返回、函数体不会执行;400 常在路径参数解析;而'接口成功但库里没数据'只能靠双端校验发现。**"
