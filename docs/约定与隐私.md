# 约定与隐私(开发规范)

> 目的:让两个人(你和未来的协作者)看同一份代码时理解一致;让开源时不出隐私事故。

---

## 1. 命名

| 对象 | 规则 | 例 |
|---|---|---|
| 类 | 大驼峰 | `HttpClient`、`TodoApi` |
| 函数/变量 | 小写下划线 | `create_todo`、`todo_id` |
| 常量 | 全大写 | `BASE_URL`、`MAX_TITLE_LEN` |
| 测试文件/函数 | `test_` 前缀 | `testcases/test_todos_crud.py::test_create_todo_returns_201` |
| 测试函数名句式 | `test_<对象>_<场景>_<预期>` | `test_delete_todo_twice_returns_404` |
| fixture | 名词(它是一份资源) | `api`、`todo_api`、`db`、`auth_api` |
| 错误码 | 大写下划线 | `INVALID_PARAM`、`ACCOUNT_LOCKED` |

## 2. 断言纪律

| 该做 | 不该做 |
|---|---|
| 断言**系统行为**:状态码、`code`、字段值、库中数据 | 断言"我自己写死的期望值等于它自己"(自证) |
| 断言 `code`(稳定) | 精确断言 `message` 文案(会改) |
| 失败信息写清原因:`assert row is not None, f"库里查不到 id={todo_id}"` | 只写 `assert row` |
| mock 用例优先断言**请求**(`httpserver.log`) | 只断言我们编造的响应 |
| 超时用例顺手 `assert httpserver.handler_errors == []` | 让 handler 的异常被静默吞掉 |

## 3. 代码规范

- **ruff** 统一检查与格式化:`ruff check --fix . && ruff format .`
- 行长 ≤ 100;导入排序交给 ruff
- 不在模块级写会执行的代码(实验脚本放 `scratch/`,用 `if __name__ == "__main__":` 保护)
- 不在 `utils/`、`api/` 里写断言
- 打印调试用 `logging`(阶段 C 起),不再新增 `print`

## 4. 分支与提交

| 项 | 约定 |
|---|---|
| 主分支 | `main`,**任何时候都要能跑绿** |
| 功能开发 | `feat/多环境配置`、`feat/yaml-数据驱动` |
| 修缺陷 | `fix/token-过期重取` |
| 提交信息 | `feat: 支持 yaml 数据驱动` / `fix: 修正软删除查询条件` / `docs: 补充接口契约` / `test: 新增待办分页组合用例` / `chore: 更新依赖` |
| 提交粒度 | 一个提交做一件事;先跑 `pytest -m "not network"` 再提交 |

## 5. 隐私与开源红线

### 绝不提交

| 类别 | 例子 | 防护手段 |
|---|---|---|
| 密钥 | `SECRET_KEY`、云服务/AI 的 API key | 放 `.env`(已 gitignore)或 CI Secrets |
| 账号密码 | 数据库口令、真实测试账号 | `.env.example` 只放占位符 |
| 个人信息 | 真实姓名、学号、手机号、**私人邮箱** | Git 提交身份用 **GitHub noreply 邮箱** |
| 本机路径/主机名 | `/home/roin`、`roin-ASUS` | `logs/`、`scratch/`、`archive/` 已排除 |
| 真实业务数据 | 实习公司的接口、数据、内部文档 | 公开仓库只放自建服务的假数据 |

### 提交前三件事

```bash
git status                 # 有没有意外文件(.env / *.db / logs)
git diff --cached          # 逐行看这次要提交什么
grep -rInE "(secret|api[_-]?key|password)\s*[:=]" --exclude-dir=.git .   # 粗筛硬编码密钥
```

### 上线开源前的检查清单

- [ ] `git log --format='%an <%ae>'` 确认提交身份是 noreply 邮箱
- [ ] 仓库里搜不到真实姓名/学号/手机号/`/home/roin`
- [ ] `.env`、`*.db`、`logs/`、`scratch/`、`archive/` 未入库
- [ ] README 里没有内部项目名、内部接口地址
- [ ] `SECRET_KEY` 之类改成从环境变量读取,并有明确的默认值提示(不允许生产默认值)

## 6. 每个目录必须有 README

新增目录时,同时新增该目录的 `README.md`,至少写清三件事:

1. **放什么**(职责边界)
2. **谁负责/什么状态**(已完成 / 待实现)
3. **怎么跑或怎么用**(命令、示例)
