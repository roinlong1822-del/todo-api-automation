## 1. 本项目现在是什么环境

| 项 | 现状 | 谁建的 |
|---|---|---|
| Python 解释器 | 系统 Python 3.12.3 | 系统 |
| 虚拟环境 | `~/study/test/.venv`(工作区根,一个 venv 服务所有项目) | **你**(学 pytest 时建的) |
| 依赖清单 | `api_server/requirements.txt`(**锁定精确版本**) | AI 建,你应能解释为什么锁 |
| 配置 | `.env`(本地,不入库)+ `.env.example`(模板) | AI 建 |
| 服务 | `uvicorn api_server.app.main:app --port 8000` | AI 建 |
| 测试运行 | 仓库根 `pytest`(配置 `pytest.ini`:pythonpath/testpaths/norecursedirs) | AI 建,你踩过它失效的坑 |

## 2. 你该能回答的 8 个问题(面试版)

| # | 问题 | 要点 |
|---|---|---|
| 1 | 为什么要用虚拟环境? | 项目级依赖隔离:避免 A 项目要 requests 2.28、B 项目要 2.34 时互相覆盖;也避免污染系统 Python |
| 2 | venv 和 conda 的区别? | venv 只管 Python 包(标准库自带);conda 还能管非 Python 依赖(如 CUDA、系统库),体积更大 |
| 3 | `requirements.txt` vs `poetry/uv` 的 lock? | 前者是"清单",后者能锁定**整棵依赖树 + 哈希**;小项目用前者够,团队/生产更稳用后者 |
| 4 | 怎么保证本地和 CI 环境一致? | 三件套:**相同 Python 版本 + 锁定依赖版本 + 相同的启动命令**;更彻底是容器化(Docker) |
| 5 | 多 Python 版本怎么管? | pyenv / uv 切换;CI 里 `actions/setup-python` 指定版本 |
| 6 | 密钥/账号怎么管? | 本地 `.env`(gitignore)、CI 用 **Secrets**;`.env.example` 只留占位符;代码里只从环境变量读 |
| 7 | 部署/测试怎么切环境? | 一份代码 + 不同配置(`config/*.yaml`)+ 环境变量覆盖(`APP_ENV=test`);**用例里不出现 URL** |
| 8 | pytest 怎么找到你的代码? | rootdir 与 `pytest.ini` 位置决定配置生效范围;`pythonpath` 把源码目录加进 `sys.path`;conftest 逐层向上收集 |

> 第 8 条你已经亲身踩过:配置放在 `api_test/` 而我在仓库根跑 → `norecursedirs` 没生效、实验探针被收集。**这就是"环境机制"的现实教训**,比背书有用。

## 3. 我为什么替你搭好环境与骨架(取舍说明)

| 我做了 | 理由 |

| 目录骨架 + 每层 README + `pytest.ini` / `ruff.toml` / `.gitignore` / `.env.example` | 属于**约定与脚手架**:重复性高、做错了要返工,但对能力提升的边际收益低 |

| pytest 配置统一到仓库根、CI 目录预留 | 同上(但 CI 的 workflow 会留给你写) |

|---|---|

**核心取舍**:你的时间余额只有到 12 月投递约 8 周。**把"脚手架"这类一次性、可复用、错了要返工的工作交给我,把"会被追问、能体现能力"的部分留给你。**

## 4. 但这个取舍有真实缺口 —— 三件事你要补

### ① 能讲清"这座框架为什么长这样"
面试官会问"从 0 到 1 搭框架"的**决策过程**。补法:关掉文档,用自己的话讲一遍(录音 3 分钟):
> 为什么分四层?去掉 `api/` 会怎样?为什么断言不写在封装层?为什么数据隔离要用 fixture + 回滚?

答不上来的层,就是没长在你身上。

### ② 亲手做一次"从零搭建"(30 分钟,练手不污染仓库)
```bash
mkdir -p /tmp/from-scratch && cd /tmp/from-scratch
python3 -m venv .venv && source .venv/bin/activate
pip install pytest requests
git init -b main
mkdir -p tests
cat > conftest.py <<'EOF'
import pytest, requests
@pytest.fixture(scope="session")
def api():
    return requests.Session()
EOF
cat > tests/test_demo.py <<'EOF'
def test_httpbin(api):
    r = api.get("https://httpbin.org/status/200", timeout=5)
    assert r.status_code == 200
EOF
pytest -v          # 跑通
git add -A && git commit -m "chore: 最小测试工程"
```
**做完你就把"环境 + 框架最小骨架"完整过了一遍手**:venv、依赖安装、git、conftest、fixture、用例、运行。

### ③ 环境类问题要能张口就答
背下第 2 节的 8 问(尤其是 1、4、6、7),它们出现的频率远高于"你写过多少用例"。
