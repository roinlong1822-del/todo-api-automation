## 1. 任务一 · `AuthApi`(约 40 分钟)

**新建** `api_test/api/auth_api.py`。

### 契约事实(来自 `docs/API_SPEC.md` §1、§2)

| 接口 | 请求 | 成功 | 失败 |
|---|---|---|---|
| `POST /login` | `{"username": ..., "password": ...}` | 200 `{"token": str, "expires_in": int}` + 响应头 `Token-Expires-At` | 400 `INVALID_PARAM` / 401 `INVALID_CREDENTIALS` / 403 `ACCOUNT_LOCKED` |
| `GET /users/me` | 头 `Authorization: Bearer <token>` | 200 `{"id": int, "username": str}` | 401 `UNAUTHORIZED` |

错误响应体统一是 `{"code": "...", "message": "..."}`(message 会改,**只断言 code**)。

### 骨架

```python
"""认证接口封装:登录、查询当前用户。"""

import requests

from utils.http_client import HttpClient


class AuthApi:
    def __init__(self, client: HttpClient, token: str | None = None) -> None:
        self.client = client
        self.token = token

    def login(self, username: str, password: str) -> requests.Response:
        """POST /login → 200 {token, expires_in};密码错 401;锁定 403。"""
        return self.client.post("/login", json={"username": username, "password": password})

    def me(self) -> requests.Response:
        """GET /users/me → 200 {id, username};无 token / token 无效 → 401。"""
        # 你来写:GET /users/me,带上 self._headers()

    def _headers(self) -> dict[str, str]:
        """Bearer 前缀是业务知识,留在本层。"""
        return {"Authorization": f"Bearer {self.token}"} if self.token else {}
```

`login` 已经给全了 —— 它是本层的**范式**:`路径 + json= + return`,不做任何判断。
`me` / `_headers` 你补。

### 常见错误

| 错误 | 症状 | 正解 |
|---|---|---|
| `client.post("/login", data={...})` | 400,服务端说参数缺失 | 用 `json=`(它会自动设 `Content-Type: application/json`) |
| 路径少开头斜杠 `"login"` | `InvalidURL` / 拼成 `http://127.0.0.1:8000login` | 所有路径以 `/` 开头 |
| 在 `login` 里 `assert r.status_code == 200` | 密码错、锁定的用例没法测 | 本层不 assert |
| `_headers()` 返回 `{"Authorization": self.token}` | 拿到 401 | 少了 `Bearer ` 前缀 |

## 2. 任务二 · `TodoApi`(约 45 分钟)

**新建** `api_test/api/todo_api.py`。四个方法,**签名照抄 README §3**,你来填实现。

### 契约事实(`docs/API_SPEC.md` §3–§6)

| 接口 | 关键点 |
|---|---|
| `POST /todos` | 成功 **201**;`title` 必填、长度 1–100;`priority` 1–3 默认 1;响应回显 `id/title/priority/status` |
| `GET /todos/{id}` | 200 / 404 `NOT_FOUND` / 403 `FORBIDDEN` |
| `GET /todos` | query:`page`(≥1 默认 1)、`size`(1–50 默认 10)、`keyword`、`status`;响应 `{total, page, size, items}` |
| `DELETE /todos/{id}` | **204 无 body**;不存在/重复删 → 404(软删除) |

### 三个必须处理的细节

1. **`todo_id: int | str`** —— 传非数字(如 `"abc"`)要能发出去,服务端返回 400。
2. **`keyword` / `status` 为 `None` 时不发该 query 参数**:
   ```python
   params = {k: v for k, v in {...}.items() if v is not None}
   ```
3. **请求头**:每个方法都带 `self._headers()`(`headers=` 参数)。

### 自查(`api_test/scratch/todo_check.py`)

一条链路走完,并确认每一步的状态码:

```python
from api.auth_api import AuthApi
from api.todo_api import TodoApi
from config.loader import load_config
from utils.http_client import HttpClient

cfg = load_config()
client = HttpClient(cfg["base_url"], cfg["timeout"])
token = AuthApi(client).login("tester", "Passw0rd!").json()["token"]
todo = TodoApi(client, token)

r = todo.create_todo("链路自查 todo", priority=2)
print("① 创建:", r.status_code, r.json())
tid = r.json()["id"]

print("② 查询:", todo.get_todo(tid).status_code, todo.get_todo(tid).json()["title"])
print("③ 列表信封:", {k: v for k, v in todo.list_todos(size=2).json().items() if k != "items"})
print("④ 关键词过滤:", [t["title"] for t in todo.list_todos(keyword="链路").json()["items"]])
r_del = todo.delete_todo(tid)
print("⑤ 删除:", r_del.status_code, "body 长度 =", len(r_del.content))
print("⑥ 重复删除:", todo.delete_todo(tid).status_code)
print("⑦ 删除后再查:", todo.get_todo(tid).status_code, todo.get_todo(tid).json())
print("⑧ 非数字 id:", todo.get_todo("abc").status_code)
print("⑨ 未鉴权创建:", TodoApi(client).create_todo("x").status_code)
```

**期望输出**

```
① 创建: 201 {'id': 5, 'title': '链路自查 todo', 'priority': 2, 'status': 'pending'}
② 查询: 200 链路自查 todo
③ 列表信封: {'total': 4, 'page': 1, 'size': 2}      ← total 看你库里实际有多少条
④ 关键词过滤: ['链路自查 todo']
⑤ 删除: 204 body 长度 = 0          ← 204 就是"没有 body"
⑥ 重复删除: 404                     ← 软删除:第二次删除也找不到
⑦ 删除后再查: 404 {'code': 'NOT_FOUND', 'message': ...}
⑧ 非数字 id: 400
⑨ 未鉴权创建: 401
```

> - `id` 和 `total` 的具体数字**取决于库里现有数据**(刚 reset 过是 `id=5`、`total=4`),所以**用例里绝不能写死** —— 这正是"id 从响应取、期望值从接口算"的原因。
> - ⑤ 和 ⑥ 是一对,别写重了:第一次删除拿 204,**第二次**删除才是 404。`r.content` 对 204 是空字节串 `b""`,所以长度 0。

### 3.2 在 `api_test/conftest.py` 里加 4 个 fixture

```python
@pytest.fixture(scope="session")
def auth_api(server_api) -> AuthApi:
    """未鉴权通道:登录接口用它。"""

@pytest.fixture(scope="session")
def token(auth_api) -> str:
    """tester 的 token,整个会话只登录一次。"""

@pytest.fixture(scope="session")
def todo_api(server_api, token) -> TodoApi:
    """已鉴权通道:绝大多数待办用例用它。"""

@pytest.fixture
def anon_todo_api(server_api) -> TodoApi:
    """未鉴权通道:401 用例用它。"""
```

**要点**

- `token` fixture 里**可以也应该 assert**:
  ```python
  r = auth_api.login(TESTER["username"], TESTER["password"])
  assert r.status_code == 200, f"登录失败,后续用例无法进行: {r.status_code} {r.text}"
  return r.json()["token"]
  ```
  这和"业务层不 assert"**不矛盾**:业务层不 assert 是为了让异常用例走得通;fixture 里 assert 是**前置条件检查** —— 环境都没准备好,后面 20 条用例全红没有意义,不如在这里立刻失败并说清原因。
- 用 session 作用域:token 只登录一次(TTL 3600 秒,够)。`anon_todo_api` 用 function 作用域无妨(它没有状态)。
- 顺序:先写 `auth_api`,再写 `token`,最后写 `todo_api` —— pytest 会按依赖注入自动排序,你不用管。

## 4. 任务四 · 第一批业务用例 7 条(约 60 分钟)

**新建** `api_test/testcases/business/test_auth.py`(5 条)与 `test_todos_crud.py`(2 条)。

### `test_auth.py`

| # | 用例名 | 操作 | 断言 | 为什么值得写 |
|---|---|---|---|---|
| 1 | `test_login_success_returns_token` | `auth_api.login(tester)` | 200;`token` 是非空 `str`;`expires_in > 0`;**且响应头 `Token-Expires-At` 存在** | 顺带验证"自定义响应头"真的发出了 —— 契约里写了但容易被实现漏掉 |
| 2 | `test_login_unknown_user_returns_401` | 用**不存在的用户名**登录 | 401;`code == "INVALID_CREDENTIALS"` | 零副作用。**不要拿 tester 试错密码** —— 3 次会锁号 |
| 3 | `test_me_without_token_returns_401` | `AuthApi(server_api).me()` | 401;`code == "UNAUTHORIZED"` | 鉴权缺失路径 |
| 4 | `test_me_returns_current_user` | 带 token 调 `me()` | 200;`username == "tester"`;`id` 是 `int` | 证明 token 真的对应到了正确的人(不是随便放行) |
| 5 | `test_me_with_forged_token_returns_401` | 传 `"forged.token"` | 401;`code == "UNAUTHORIZED"` | **信息量最高的一条**:能抓出"只看头存在、不验签名"的实现缺陷 |

### `test_todos_crud.py`

| # | 用例名 | 操作 | 断言 |
|---|---|---|---|
| 6 | `test_create_get_delete_roundtrip` | 创建 → 查 → 删 → 再查 | 201 且回显 `title`/`priority`/`status=="pending"`;**id 从响应里取,不硬编码**;查询 200 且 `title` 一致;删除 204 且 `r.content == b""`;再查 404 且 `code == "NOT_FOUND"` |
| 7 | `test_list_returns_pagination_envelope` | `list_todos(size=2)` | 200;响应含 `total/page/size/items` 四个键;`page==1`、`size==2`;`len(items) <= 2`;**`total >= len(items)`**(别把 `total` 当 `len(items)`) |

### 写的时候守三条

1. **从 fixture 拿通道**:`def test_x(todo_api):`,不 new 客户端、不写路径、不写 `requests`。
2. **先写断言,再写调用** —— 先想清"我要证明什么",再去调接口。
3. **每条用例自问**:「如果服务端把这个逻辑写错了,我这条会不会红?」不会红 → 这条用例是在凑数。
   (这条自检正是故障注入要验证的东西,见 `../api/README.md` §7。)
