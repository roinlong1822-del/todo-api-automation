> 用途:解决"旧代码删掉后不知道写什么"。**照着这张表逐条填,填完就是一套像样的接口测试套件。**
> 数据源:`api`(本地 mock,默认)/ `remote_api`(真外网,仅冒烟)

---

## 一、五层思考框架(以后任何接口都这么想)

| 层 | 问什么 | 对应断言 |
|---|---|---|
| ① HTTP 层 | 请求成功了吗?格式对吗?快吗? | `status_code`、`Content-Type`、`elapsed` |
| ② 契约/结构层 | 字段都在吗?类型对吗? | 字段存在性、`isinstance`、嵌套结构、数组长度 |
| ③ 参数层 | 我传的参数真的发出去了吗? | mock 匹配 `query_string` / `json` body |
| ④ 业务/数据层 | 值对不对?列表内容对吗? | 字段值、列表元素、分页、状态变化 |
| ⑤ 异常层 | 出错时会怎样? | 404、400、401、超时、5xx |

> **测开的分数主要在 ③⑤ 两层**——大多数人的用例只测了 ①②,而 bug 最爱藏在参数传递和异常路径里。

## 三、httpserver 能造什么(决定你能测什么)

| 需求 | 写法 |
|---|---|
| JSON 200 | `httpserver.expect_request("/todos/1").respond_with_json(TODO_1)` |
| 指定状态码 | `...respond_with_data(status=404)` / `respond_with_json(TODO_1, status=201)` |
| 延迟 / 超时 | `...respond_with_handler(slow_handler)`,handler 里 `time.sleep(3)` |
| **校验 query 参数** | `expect_request("/todos", query_string={"userId": "1"})` |
| **校验 POST body** | `expect_request("/todos", method="POST", json={"title": "x"})` |
| **校验请求头** | `expect_request("/todos/1", headers={"Authorization": "Bearer t"})` |
| 只匹配一次 | `expect_oneshot_request(...)` |

> **隐含断言**:如果用例实际发出的请求和 `expect_request` 的条件匹配不上,mock 会返回 500 → 你的用例就红了。所以"匹配条件"本身就是一种契约断言:**参数没传、路径写错,会当场暴露**。
